# Assetto Launcher

I started this project roughly a year ago with a design in mind, made in Figma. I didn't have the coding skills nor the idea sorted out, but thanks to AI I could make this project come to life, and I think it's worth a shot. The code is open source and I would love the community's feedback on things to improve. I think the foundation is pretty good, and while some features may not be as good or as polished as I would like them to be, they are better than nothing.

This is basically just a launcher where you can see all your installed mods from any Assetto Corsa game, and on top of that you can start races with a predefined car and track, like in Content Manager. For the games that aren't the original Assetto Corsa, the car and track are added to a save file, so that when you go into the game after choosing them and launching the game through the launcher, it'll set them as the default. So you already have everything selected. For some games, you can even change the time, weather, opponents and more.

Support for Linux has come with v0.2.0. Still in beta stage until it is fully polished

Personally, I really like the project, and I hope the community does too.

The launcher is completely free forever. If you'd like to support it, you can [buy me a coffee on Ko-fi](https://ko-fi.com/gperpas) ☕

## Download

**[Visit the Assetto Launcher website](https://www.assettolauncher.net/)** or 
**[Download the latest version from Github](https://github.com/Zelbrad/AssettoLauncher/releases/latest)**, then pick one of:

- **`Assetto-Launcher-Setup-<version>.exe`**: installs for your Windows user only (no admin prompt), with a Start Menu entry and an optional desktop shortcut. Installing a newer version keeps your settings.
- **`assetto-launcher-release.zip`**: portable. Unzip anywhere you can write to and run `assetto-launcher-win_x64.exe`.

Needs Windows 10 (1803 or later) or 11 and the games from Steam. It works offline; news, store prices and update checks need a connection.

### "Windows protected your PC"?

The launcher isn't code-signed yet, so Windows SmartScreen warns about it until enough people have run it. Click **More info → Run anyway**. Each release lists the installer's SHA-256 hash, so you can check you have the genuine file (`Get-FileHash <file>` in PowerShell).

### Linux (beta)

The games run through Steam's Proton, and the launcher finds each game's files inside its Proton prefix (`steamapps/compatdata/<appid>/pfx/drive_c/users/steamuser/...`). Run each game once from Steam first so that prefix exists.

- **Download:** `assetto-launcher-linux_x64.tar.gz`. Unpack it anywhere and run `./assetto-launcher-linux_x64`. It's portable and doesn't update itself: a new version opens the release page.
- **Needs:** WebKitGTK (the `webkit2gtk` package), `curl`, `xdg-utils`, `procps` (`pgrep`), and `bsdtar` (`libarchive-tools`) or 7-Zip (`p7zip`) to install mods from archives.
- **Steam:** native, Debian, Flatpak and Snap installs are detected. Steam has to be running to start games.
- **Quick Drive:** AC's `acs.exe` is started in AC's prefix with the Proton build that last ran the game (with `WINEDLLOVERRIDES="dwrite=n,b"` when Custom Shaders Patch is installed, so Wine loads CSP's `dwrite.dll`; to start AC from Steam with CSP, Settings shows the launch option to copy). EVO starts through `steam -applaunch`. ACC and Rally are set up and then started through Steam, the same as on Windows.

### Testing on Linux

1. Each game shows as installed in the sidebar, and Settings → Game folders points at the right places.
2. Mods: cars, tracks, liveries, screenshots and replays show up for every game.
3. Install a mod from a `.zip`, a `.7z` and a `.rar`. Each one lands in the right folder.
4. Quick Drive starts every game with the chosen car and track (AC on track, ACC/Rally in their menus, EVO in Single Player).
5. Settings → Backups: Back up now, Restore and Delete all work, and "Open folder" buttons open the file manager.
6. Resizing, moving, maximizing and minimizing the window work (moving a window from inside the app may not work on Wayland).

When something fails, send `neutralinojs.log` from the launcher's folder.

## About

A lightweight launcher for the four Assetto Corsa games: AC, ACC, EVO and Rally. It lets you browse installed mods visually, read the official Steam news, launch the games, and drive the Academy: events with bronze, silver and gold medals for AC, EVO and Rally (and platinum on EVO and Rally time trials).

Built with [Neutralino](https://neutralino.js.org/), which uses the WebView2 runtime that comes with Windows: no Electron or Chromium bundle. The installer is about 7.5 MB.

## Build from source

1. Install [Node.js](https://nodejs.org/).
2. `npx @neutralinojs/neu update` fetches the Neutralino runtime into `bin\`.
3. `run-dev.bat` runs it straight from `resources\`; `build.bat` packages it (see below). The installer needs [Inno Setup 6](https://jrsoftware.org/isinfo.php).
4. Linux: `./run-dev.sh` runs it, and `./build-linux.sh` makes `dist/assetto-launcher-linux_x64.tar.gz`.

## Releasing a new version

The launcher checks this repo's latest release at startup and offers it to everyone in a red bar along the bottom (Update now / What's new / Skip this version / close = ask again next launch; Settings → About → Check for updates asks on demand). For that to work:

1. Bump `"version"` in `neutralino.config.json` (e.g. `0.2.0`).
2. Run `build.bat`; it makes `dist\Assetto-Launcher-Setup-0.2.0.exe` and the portable zip.
3. On GitHub: **Releases → Draft a new release**, tag `v0.2.0` (the same version with a `v`), attach both files (and the Linux build, `dist/assetto-launcher-linux_x64.tar.gz` from `build-linux.sh`), write what's new, **Publish**. Drafts and pre-releases aren't offered.

Installed copies download the setup, check its SHA-256 against the one GitHub lists for the file, run it silently (settings are kept) and start the new version. Portable copies open the release page instead.

Rally cards are square |

Install folders are found automatically through Steam (`libraryfolders.vdf` + `appmanifest_*.acf`). You can change any folder in **Settings**.

- **Mods vs Kunos (AC):** content counts as a mod when its `author` isn't Kunos, or when its folder isn't a known Kunos ID.
- **Enable / disable (EVO, Rally):** the launcher renames the files with a `.disabled` suffix. The game ignores renamed files, and enabling them again just removes the suffix. Rally loads every folder under `Liveries\<Car>`, so a disabled custom livery is moved to `Documents\My Games\acr\Liveries (disabled)\<Car>\` instead.
- **Uninstall:** a mod's detail page has an Uninstall button (click it twice to confirm). Everything that belongs to the mod goes to the Recycle Bin, so it can be restored: the AC folder, the ACC livery plus the car files that use it, the EVO package plus its image, the EVO livery plus its garage car, or the Rally livery folder or pak trio plus its image. Official content can't be uninstalled.
- **Quick Drive (navbar):** works the same whichever game is selected in the sidebar. The dialog has a tab per game (Assetto Corsa, EVO and Competizione; Rally is shown but not available) and opens on the sidebar's game when it has Quick Drive, else on the one used last. The **Session settings** button in its header opens a sheet with everything the game lets you set for the session (below); the header and footer show a summary. Closing the dialog without launching still remembers the car, livery/skin, track, layout and session.
- **Quick Drive (AC):** car, skin, track/layout and session are written to `Documents\Assetto Corsa\cfg\race.ini`, then `acs.exe` starts directly, the same way Content Manager does. The keys, ranges and formulas are the ones AC's own launcher uses (`launcher\themes\default\js\ui.js`); with Custom Shaders Patch, the CSP keys are the ones Content Manager writes. The first time, the original files are backed up as `race.ini.launcher-backup` and `assists.ini.launcher-backup`.
  - **Modes:** Practice (length or unlimited), Hotlap, Race (laps, starting position: last, random or a slot) and Race Weekend (practice or skip, qualifying, race laps), as `[SESSION_n]` sections.
  - **Opponents (races):** count (up to the layout's pit boxes − 1), strength (`[RACE] AI_LEVEL`, 80–100 %), variation (each car's `AI_LEVEL` below 100) and aggression (`AI_AGGRESSION`, 0–100). They drive your car in its other skins, named from each skin's `ui_skin.json` or AC's `namesnat.txt`. Layouts without `ai\fast_lane.ai` can't have opponents and are marked "no AI line".
  - **Conditions:** time of day (08:00–18:00, `SUN_ANGLE` = 16° per hour from 13:00), time speed, weather (`content\weather`), air temperature (10–36 °C), track temperature (Auto uses AC's launcher formula with the weather's `TEMPERATURE_COEFF`), track grip (the presets in `cfg\templates\tracks.ini`) and penalties. With Content Manager's CSP keys present, `__CM_WEATHER_TYPE` is kept in step with the weather, and the previous track's `__TRACK_*` location keys are removed.
  - **Wind:** speed, gusts and direction, as `[WIND] SPEED_KMH_MIN`, `SPEED_KMH_MAX` (speed + gusts) and `DIRECTION_DEG`.
  - **With Custom Shaders Patch** (`csp.js`; what CSP supports comes from `extension\config\data_manifest.ini [FEATURES]`, as in Content Manager): with Weather FX on (and `WEATHERFX_LAUNCHER_CONTROLLED`), the weather is one of CSP's weather types (Content Manager's `WeatherType` numbers: clear to overcast, fog, haze, drizzle, rain and thunderstorms in three strengths, snow and sleet when CSP has `SNOW`, hail, windy…), written as `[LIGHTING] __CM_WEATHER_TYPE` with `__CM_WEATHER_CONTROLLER` (CSP's default `base`, or another controller that follows the chosen weather). Controllers that pick the weather themselves (`FOLLOWS_SELECTED_WEATHER = 0` in their `manifest.ini`, e.g. Live and Schedule) are listed as weathers and use their saved settings. `[WEATHER] NAME` gets a preset made for that type (`[__LAUNCHER_CM] WEATHER_TYPE` in its `weather.ini`, as Sol's have), else the closest Kunos one. `CONDITIONS_24H` allows any time of day (`SUN_ANGLE` beyond ±80°; the road temperature blends from 18:00 to the next 08:00, as Content Manager does), and `CONDITIONS_SPECIFIC_DATE` a date (`__CM_DATE`, seconds since 1970) for the sun's position and the season. Picking rain while Rain FX is off shows a note.
  - **Assists** (`cfg\assists.ini [ASSISTS]`, as AC's launcher and Content Manager write it): AC's Gamer, Racer and Pro presets (`cfg\templates`) or custom; ABS and traction control (off, the car's factory setting, on), stability control, automatic clutch, gear shifts and blips, ideal line, mechanical and visual damage, fuel use, tyre wear (0–3×), tyre blankets and slipstream (1–5×). They're read back from the file when Quick Drive opens.
  - Tracks without any `.kn5` (unowned DLC placeholders, or mod layouts that need such a DLC) aren't listed.
- **Quick Drive (EVO):** pick the session, track/layout and car, and the launcher starts EVO through Steam (`steam.exe -applaunch 3058630 -no_intro`). In EVO, **Single Player** shows everything already selected. Started directly, the exe can fail Steam's ownership check. The session sheet has what EVO's own Game Mode and Weather pages can change, with the same ranges: mode (Practice, Race, Race Weekend); each session's length, start time and time speed (Race: laps or time, starting position); the AI grid (automatic or EVO's custom grid, opponents up to the layout's limit, skill from/to 80–100 %, single make); weather preset, static/dynamic and initial grip (Green, Fast, Optimum). EVO has no temperature setting. Field numbers come from the protobuf descriptors embedded in the EVO exe (`GameModeSelectionClientCommands.proto`). The launcher edits these save files under `Saved Games\ACE`, keeping a `.launcher-backup` of each:
  - **Sessions:** in `GameModes\GameModeType_PRACTICE|INSTANT_RACE|RACE_WEEKEND.gamemodesave`, each session's `track_item` (5), duration (2) and type (3, time or laps), `time_of_day` (4: hour, minute, time multiplier) and, for Race, `starting_position` (22). The AI grid is in the first session: `grid_type` (6), `num_opponents` (7), `single_make` (12), `min_strength`/`max_strength` (30/31) and `aggressivness` (32: always 1, Safe; the game ignores its other value, "Preview"). Practice uses each layout's "Time Attack" entry in `system\track_containers.table`, the races its "Race" entry. A mode EVO hasn't opened yet starts from its default save in `content.kspkg`.
  - **Selected mode and weather:** `GameModes\gamemode.lastgamemode` (`type` = 1, `weather_type` = 2); static/dynamic (2) and initial grip (6) go into the selected preset's `weather_data` entry, as EVO's weather page does.
  - **Car:** the current-car ID (field 4) in `ProfileData\<profile>\OpenData\garage.drivergarage`.

  EVO creates a car ID per exact configuration (car + mechanical preset + livery) and doesn't expose them. So only configurations it has already used can be picked; garage cars (`SavedCars`) can't be selected this way, because EVO falls back to another car. Every car is listed, and cars without an ID are marked "Not used yet". The launcher reads IDs from EVO's logs: the preset screen logs `Selected <car> <mech preset> <visual preset>`, and the last such line before `Set new car <id> …` names that ID's livery. It also checks `last_season.seasondefinition`. A selected car shows a compact **Livery** row with each known livery's thumbnail and name (`generated\thumbnails\<car>-<mech>-<visual>.texture` and the `.visualcarpreset` / `.mechanicalcarpreset` names, from `content.kspkg` or the mod package), cached in `.cache\evo\extras\`. EVO keeps only its last ~10 logs, so found IDs are saved in `.cache\evo\known-cars.json`.
- **Brand rail (Mods > Cars, AC and EVO):** the same brand column as Quick Drive filters the car grid (AC: each brand's car badge; EVO: its brand logos from the package, cached by `readEvoExtras`). It follows the search and the Mods/All filter. On these pages the page itself doesn't scroll: the rail and the car grid scroll separately, and picking a brand keeps the rail where it is. Car cards show the brand logo top left (AC: the car's badge; EVO: its brand's logo, set as `badge` once the logos load), and the detail page shows it above the title.
- **Window:** borderless (own title bar), so Windows gives it no resize frame: `windowGrips` puts thin grips on the edges and corners that resize it through `Neutralino.window.setSize`/`move` (hidden while maximized; pointer moves that arrive before the window's size is known are replayed). The default size, 1540×795, is also the minimum. Every resize goes through `setWindowSize` with `resizable: false`: Neutralino's `setSize` otherwise adds `WS_THICKFRAME`, which shows as a strip above the title bar (restoring the saved size at launch does too, so startup calls it once, and again when a window that started maximized is restored). `windowFrame` asks Windows 11 for small rounded corners (`DwmSetWindowAttribute`, `DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_ROUNDSMALL`), which keeps the window shadow. Asked for, the corners and the 1 px border stay while maximized and show the window behind at the screen edges, so a maximized window gets square corners and no border (`DWMWCP_DONOTROUND`, `DWMWA_BORDER_COLOR` = none). A window that starts maximized reaches 8 px past every edge of the work area (the screen minus the taskbar) and is fitted to it. One hidden PowerShell stays open for this (`spawnProcess`, commands on its stdin, per-monitor DPI aware so display scaling doesn't round it off), so the switch is instant; older Windows ignores the DWM attributes.
- **EVO livery names:** a car EVO loads from the garage at session start has no "Selected" log line before it; the car menu's first "Selected" line after "Set new car" (same mechanical preset) names its livery, so `knownCars` fills it in when unknown. Visual preset `*_visual_99` is EVO's slot for an external livery: Quick Drive shows that livery's `livery_thumbnail.png` and name from `ExternalLiveries` (matched to the car through its `car_guid` in SavedCars) instead of the package's plain white car.
- **Quick Drive picker (AC, EVO, ACC and Rally):** car column with a thin brand rail (EVO's `uiresources\branding\oem\<brand>\logo.texture`; for AC, the cars' `ui\badge.png`), a car grid and a one-line skin/livery row (the selected car's card shows the chosen one); track column with layouts and a track grid. Both columns have their own search. Quick Drive is a page (navbar), not a dialog: the game sidebar is hidden there (`#app.qd-mode`), and `qdPage` only swaps in a game's page if it's still the one asked for (`state.qdWant`), so switching tabs keeps the current page dimmed until the next game's lists are ready, then fades them in. Rally locations show a photo cover (`img/rally/<location>.jpg`, Wikimedia Commons, credits in `img/rally/CREDITS.txt`) with the country's flag in the corner (Wales: the Welsh flag); ACC tracks show their country's flag (`img/flags/<iso>.png`, flagcdn.com). Rally's own car pictures, logos and stage maps exist (`acr/Content/Data/UITextures/Cars`, `CarsLogo`, `Tracks/Tracks/T_*_Map`, found through the IoStore directory index) but are Oodle-compressed, and no Oodle library ships with the games. Rally Quick Drive also sets the main menu car, which is the most recently driven one (read at startup): the chosen car gets "now" in the car → last-driven map (`int32 k, k × FString car, 8 zero bytes, int32 m, m × (FString car, int64 .NET ticks, local time)`), added if missing. It sets the livery too: the save ends with a car → livery map (`int32 count, count × (FString car, FString livery)` up to the end of the file; a car's own livery is its id, a folder livery `usergen_<folder>`; tested in-game). The Livery row lists the car's own livery (or the enabled .pak that replaces it), the game's other liveries once the save has had them selected (learned, `settings.rallyLiveryIds`), and the folder liveries. `RALLY_KNOWN_STAGES` lists all 46 stages: the variants of the pacenote tables in the game's packages (`Data/Pacenote/Tables/DT_Pacenote<Stage><Variant><Direction>`) for the 9 stages with an `Environments` folder (Alsace S2 Munster, S4 Saverne; Greece S3 Elatia, S4 Loutraki; Livigno; Monte Carlo S1 Bollène/Col de Turini, S2 Sisteron; Wales S3 Hafren North, S4 Hafren South), with the save's id naming.
- **Official pictures (ACC, Rally stages):** `tools/site-images.mjs` downloads ACC's car and track pictures and Rally's stage pictures from assettocorsa.gg (`sitecatalog.js` parses the pages' `#cars` / `#stages` / `#tracks` sections) into `img/site/<game>/` with a `manifest.json` (480 px JPEGs, ~1.9 MB): 9 Rally stage photos (Greece's two aren't in the site's gallery yet: they come from the EA 0.5 news post, `RALLY_STAGE_PHOTOS`), 9 Rally stage maps (the site's `T_<stage>.png` under `<p class="font-script">` captions, `siteMaps`; `tools/map.ps1` crops them to the outline, turns the black start arrow/finish flag light grey and fits them in 160 px, kept transparent; shown on each stage button, drawn white like AC's outlines with a CSS filter so maps synced later match), 62 ACC cars (the GT2 cars aren't named there; they keep their logo) and 25 ACC tracks (the page names DLC packs instead of some tracks, so these follow ACC's alphabetical order). Rally is in Early Access, so at every launch, when online, `siteSync` asks for the Rally page with `If-Modified-Since` (the site answers 304 with no body when nothing changed; a changed page is ~70 KB compressed) and keeps pictures of stages and stage maps added since in `.cache/site` (`settings.siteExtra`; entries the launcher now ships are dropped, and so are the Rally cars older launchers synced). Rally's cars use the game's own pictures (below). `node tools/site-images.mjs rally/maps` refetches only the kinds named. Rally's Livery row selects the livery but the car keeps its picture (`keepCarImage`: Rally's livery pictures are flat textures).
- **Rally's own texts (`rallydata.js`, `resources/data/rally-game.json`):** the in-game name of every stage variant ("La Bollène-Vésubie - Turini"), the stage groups' names and descriptions, and each car's description, default livery name ("Erreffe Team 2025") and picture, in English, Spanish, French, German and Italian (pt-BR uses English). They come from the game's `Localization/Game/<lang>/Game.locres` in `pakchunk0-Windows.pak` (keys `TRACK_<STAGE>_<FULL|CUTn|SHORTn>_<FORWARD|REVERSE>`, `TRACK_STAGE_*`, `GROUP_*_DESC`, `LIVERY_*_1`; Col de Turini's Cut1-3 are its SHORT1-3). The same tool exports each stage variant's map (the whole stage with the part driven in red, start arrow and finish flag; the game's 800 px `Data/UITextures/Tracks/Tracks/<location>/…` textures, listed one by one in `MEDIA` as the game names them freely, cropped to the drawing and cut to 240 px) into `img/rally/stages/<stage id>.png`, plus `<stage id>-chip.png`, a 68 px copy with only the white stage and red part, lines thickened (~840 KB for 46 stages), listed under `media` in the JSON: Quick Drive's stage buttons show the chip instead of the site's outline, and the Mods page's stage list shows the maps. Each car's picture is the game's car-select one (`Data/UITextures/Cars/T_<car>`, 2000×972 on a transparent background, listed in `CAR_PICTURES` as the game names them freely; the tool fails on a car without one and names a picture no car uses), centred on a transparent 16:9 canvas at 82% of its width (so it also fits the 16:7 detail header) and saved as `img/rally/cars/<car id>.webp` (960×540, ~1.1 MB for 18 cars), listed as `cars.<id>.picture`: the Mods page, Quick Drive, Setups, liveries and the Academy all show it (`rallyCarPicture`). A stage or car only a newer JSON lists loads its pictures from GitHub. These come from IoStore containers (`IoStore` in the tool reads the .utoc chunk and compression-block tables and the .ucas blocks) and are Texture2D packages decoded with Pillow. That pak and those containers are Oodle-compressed, so `py tools/rally-data.py ["<Rally folder>"]` builds everything on the developer's computer (it needs `py -m pip install pyooz pillow`; pyooz is a GPL decompressor that isn't shipped); run it after a Rally update and commit the JSON and the pictures. At every launch, when online, `refreshRallyData` asks GitHub for the file on `main` with an ETag (a 304 when unchanged) and keeps a newer copy in `.cache/rally`, so released launchers get new names without an update. Stages and cars the file doesn't know keep their generic names.
- **Rally Cars and Tracks (Mods page):** the game's cars (its file index, so cars an update adds show up; the game's car picture, brand logo, class from `Vehicles/<class>`, the game's description, default livery and how many of your liveries are for it) and its stages, one card per stage group with its variants as stages (the location photo or the site's stage photo, country flag, the stage map drawn white over it, the game's description), under **All content**; **Mods** lists packages that add a car or a stage. Every .pak trio in `Paks` / `Paks\~mods` is sorted by its own file index (`rallyModContents`): a car the game doesn't have (`DA_<car>_UserLivery`) goes to Cars, a stage map it doesn't have to Tracks, anything else to Liveries, with its car read from the `Vehicles/<class>/<folder>` it replaces (from its name when the index can't be read). The mod check and the crash check before launching cover car and stage packages too. `--snapshots=<dir> --check-rally-mods` shows both tabs and a detail page of each.
- **Setups (Mods page, `setups.js`):** a Setups tab for AC, ACC and Rally, one card per car with setups (newest first, their names on it). Its window lists them on the left; the one picked shows a tab per group of the game's setup menu (`setupGroups`), on a grid of four columns: a card per wheel (front left, front right, rear left, rear right), a card per axle under them (Front under the fronts, Rear under the rears), the rest as tiles; a part fitted to every wheel (discs, calipers, pads) is shown once, or once per axle. Compare (A vs B, `compareGroups`) lays them out the same way, the differences highlighted with how much B changes each number ("+3 psi"). Export, Import (also on the tab's toolbar), Duplicate, Rename and Delete. AC: `Documents\Assetto Corsa\setups\<car>\<track>\<name>.ini` (+ `.sp`), values are AC's steps, `[CAR] MODEL` names the car (AC's own `generic\last.ini` isn't listed); ACC: `Documents\Assetto Corsa Competizione\Setups\<car>\<track>\<name>.json` (`ACC_SETUP_CARS` maps its car folders to the model numbers for names and pictures); both share their own files, deleted ones go to the Recycle Bin, imports go to the track folder picked (AC: or `generic`). Rally: the Personal setups in `%LOCALAPPDATA%\acr\Saved\SaveGames\CarSetupsDataSaveSlot.sav` (layout in `setups.js`; every value is text, e.g. `Brakes.BrakesMain.FrontBias` = `0.445000`, shown as 44.5 % with the game's own labels from `rally-game.json` `setup`, which `tools/rally-data.py` takes from the locres `CARSETUP_*` / `SETUP_*` keys for every key the cars' `Data/CarSetups/DA_<car>Presets` use). `editRallySetups` writes it only while Rally is closed: the file before goes to `.launcher-backup`, and what's written must read back identical, else the backup goes back. New entries get flags 0x02 and the local time (Rally's dates are wall-clock ticks). Each is a track container of its own (`system\track_containers.table` rows "Academy R1-1"… with the A-to-B flag, read into the catalogue as a layout's `arches`) that puts a start arch with lights and a finish arch on the layout; the launcher writes it as an Instant Race of one lap with no AI (`session.arch`), so the car starts at the arch behind the lights. GameModeType_INSTANT_RACE | <track> <container> …| <car>`, the split at the finish arch counted from the green (`changing session phase … -> 50`); restarts from the pause menu give more runs, the best counts. While EVO is open with any Academy event, the launcher reads what EVO adds to that log every 100 ms (`academyWatch`): a sprint's runs as they end (`sprintReader`), a race's finish as the player crosses the line (`raceReader`: the player's car from `SpawnVehicle(Player)`, every car's `New lap carId <guid>` since the green; the first to complete the laps wins, and each car's next crossing after that is its finish), a time trial's laps as the player completes them (`lapReader`: the player's `New lap` lines in the Practice session; the out-lap isn't logged, and the log doesn't say which laps EVO counts, so a lap with a penalty notification shown during it, `UINotificationType_SessionPenalty`, gets a "not counted" card), and any session's result as EVO saves it (`SessionResults saved into "<file>"`, read with `evoResultFile`: a race some 11 s after the player's finish, once the field is in, and again, the same file, when its results screen is left; a practice when it ends or when EVO closes). A race's card comes at the finish line and a time trial's at each lap's line; a sprint's run and a time trial's laps come from EVO's live data the moment they're done (`liveDataLap`: `total_lap_count` and `last_laptime_ms` in its graphics page), since EVO writes its log in blocks, many seconds late when little happens on track (alone in a sprint); the log's run then saves it without a second card (`recordResult` with `save: false`); the result is saved from EVO's file, with a card then only if it came out different (another position, or another best lap). Each is saved at once and shown on a small card over the game: `overlay.html`, a window of its own Neutralino process (`window.create`: transparent, borderless, always on top, not on the taskbar), told what to show through a JSON file in the temp folder (`overlayFile`); it goes when EVO closes, or on its own if the launcher stops sending its heartbeat. The card (`css/overlay.css`, markup and slide in/out in `js/overlay-card.js`) is a banner at the top centre, 12 % down the screen (`OVERLAY_TOP`: under the game's own top HUD), that slides down from above and back up: the medal on a slanted plate of its metal (dark without one, red for a run or lap that doesn't count), then the level and event and the time or place, with a line along its foot running down while it stays. Showing a window takes the focus, which mustn't happen to the game mid-lap, so the window is shown once, empty, as it starts (before EVO's window is up) and waits off the screen between cards (it would otherwise catch clicks over the game); a card moves it into place and slides in, which leaves the focus where it is. Its 100 ms check runs on a worker's clock: the web view may slow a hidden page's own timers. A short notification sound (`sounds/academy-card.mp3`, credits in `sounds/CREDITS.txt`; played by `chime.js` through Web Audio) plays from the launcher's window, the only one the web view lets make sound (an event is started with a click there). When EVO closes, only what the card didn't show is saved. **Rally:** five levels of six stages (`RALLY_LEVELS`) set in Free Practice (`writeRallySession`: stage, car, start time, fixed weather). Targets are Rally's own: the AI's time for that car and stage (`rally-game.json` `ai`, which `tools/rally-data.py` takes from `Data/Database/Main/AI/DT_AITrackVariantsCarsData`, the AI's sector timings in 100 ns ticks) with the game's medal margins (`DT_MedalPercentageModifiers`: gold 4 %, silver 20 %, bronze 35 % over it by day; more at night and in rain or snow), plus a launcher-only platinum for beating the AI's time (+1 % at night, +5/6 % in the wet; `RALLY_PLATINUM`). Platinum exists only on these time trials; races and AC's events keep three medals. **Bonus events:** each EVO and Rally level (not EVO's Sprints) has a seventh event, a step up from it (`bonus` in academy-data.js, in the game's `all` after the level's six), that opens with gold or better on all six (`bonusLocked`); it's a strip under the level, the result window names it when it opens, and Continue leads to it. **Driver level:** every event's best medal gives points, in every game (bronze 1, silver 2, gold 3, platinum 5; `driverLevel`), and going from level n to n + 1 takes n + 3 points; shown in the Academy header and in the result window, as on the cards over the game, labelled DR (and the safety rating SR): the level on a slanted red plate and a bar to the next level, named at its end (`ayLevelPlate`, `ayDrBar`; the safety rating's grade on a plate of its colour and a bar through that grade to the next one: `ayGradePlate`, `aySrBar`; the result window shows on them what the event lost or gained; the details are in their tooltips), against the level when the event started (`l.academy.driver`, so medals saved over the game count too; a level gained with nothing left to save at the end gets a toast). **Safety rating** (EVO races and race weekends started from the Academy): 0 to 99 from 50, shown as a grade (E, D, C, B, A, S at 0, 20, 40, 60, 80, 99) in the header of EVO's page and in the result window; EVO's Masters level also asks for B (`sr` in academy-data.js, `levelLocked`). It counts from the green to the player's finish (`srReader`: the session phases in the log): an impact costs 1, 3 or 5 by how much the car's damage went up (under 8, under 18, more: a tap is about 3, a hard hit 20 and more; impacts less than 2 s apart are one incident, which costs its worst impact once: `srHitExtra`), three or more wheels off the track for 0.3 s cost 1, a corner cut 2 (the lap marked invalid while off, or on its own), a penalty EVO gives (`{PENALTY_ADDED_KEY}` in the log; a jump start is `DetectorWrongPositionOnStart … (Penalty: true)`) costs 2, and a lap without any of them gives 1 back (`srLoss`, `changeSR`). Impacts, wheels off and cuts come from EVO's shared memory for third-party tools, laid out as in Kunos's SharedFileOut.h (packed to 4): `Local\acevo_pmf_physics` carDamage[5] at byte 224 and numberOfTyresOut at 244; `Local\acevo_pmf_graphics` status at 4, car_model at 3086 and is_valid_lap at 3121, checked against the layout once driving (when it doesn't match, cuts come from the log's `Showing track cut widget`). A PowerShell helper reads them, read-only, 20 times a second (`evotelemetry.js`; too long for a command line, it's written to the temp folder and run from there; it starts with the event and ends with the launcher). A cut and the penalty EVO gives for it count once (`SR_CUT_GAP`). Each change shows on a tile of its own on the screen's right edge, half way down, without sound (`overlay.html?side=right`, `srCard`): "SR" over three chevrons, down with 1 lit green (−1), 2 amber (−2, −3) or 3 red (−5), or one lit blue going up (a clean lap). **Jump starts and penalties:** a sprint run after a jump start doesn't count (`sprintReader` `state.jumps`, with a card saying so); a race EVO disqualified the player from (`penalties` / `high_penalty` in its results) isn't a finish; other penalties are in EVO's own classification. The watch reads the log up to its real end each time (`logAppend`: the size Windows reports for a file being written can lag) on a worker's clock (the web view slows a hidden page's timers once the game has been in front for a few minutes). The result is a stage record in the save with that car, in that weather, better than the one before the launch (`rallyRecords`). Levels open with 4 medals in the one before. `--snapshots=<dir> --check-academy` runs it all on a sandbox (`race.ini` written to `<dir>\academy-sandbox\cfg`, made-up `race_out.json` and EVO results, a test storage key), with snapshots of each page, window and result.

- **Video settings (AC, `acvideo.js`, Settings page):** display mode, resolution (the adapter's modes from `CIM_VideoControllerResolution`, or `xrandr` on Linux), refresh rate, vertical sync, frame rate limit (`FPS_CAP_MS` = 1000 / limit), anti-aliasing (`AASAMPLES`), anisotropic filtering and shadow map size, in `cfg\video.ini`. The resolution goes into `WIDTH`/`HEIGHT` with `[REFRESH] VALUE`, and `INDEX` is cleared, as AC's launcher does. The first change keeps `video.ini.launcher-backup`.
- **Post-processing filter (AC, `ppfilters.js`, a row of the Video settings):** a dropdown of `system\cfg\ppfilters\*.ini` (added ones, Pure's, AC's), plus **Off**. Choosing a filter sets `[POST_PROCESS] FILTER` and `ENABLED=1` in `video.ini`; Off sets `ENABLED=0`. Next to it, for the chosen filter: **Uninstall** (second click) backs the filter up, moves it to the Recycle Bin and sets `FILTER=default`. A filter's `.lua` or `<name>` / `<name>_scripts` folder goes with it. AC's own filters (`default`, `natural`, …) can't be uninstalled, and Pure's (`pure*`) are removed with Pure. Replacing or uninstalling a filter first copies it to `Documents\Assetto Launcher\Backups\ac\ppfilters\<date> <name>\` (`filter.json`), keeping the last 3 of each. **Restore** (shown when the chosen filter has a backup) puts the newest backup back: the installed version is backed up first and the restored backup is removed, so restoring again swaps them back. Backups of uninstalled filters stay in that folder.
- **Game settings backups (`backups.js`, Settings page):** copies of each game's settings, setups and progress (AC: `cfg`, `setups`, `champs`, `personalbest.ini`; ACC: `Config`, `Setups`; EVO: everything in `Saved Games\ACE` except mods, liveries, logs, replays, MoTeC, results and crash dumps; Rally: `Saved\Config\Windows`, `Saved\SaveGames`) in `Documents\Assetto Launcher\Backups\<game>\<date>\` with a `backup.json`. Copies go through PowerShell `Copy-Item` (single-quoted forward-slash paths); the launcher's `.launcher-backup` files are left out. Restoring refuses while the game runs, backs up the current state first and merges the files back. One automatic backup per game each week; the last 4 automatic ones are kept.
- **Game backgrounds (Settings page):** each game's picture on the Games tab can be swapped for the user's own (JPG, PNG or WebP). **Choose image…** copies it to `<app>\backgrounds\<game>-<time>.<ext>` (served at `/m/backgrounds`; a new name each time, so the webview never shows the old one from its cache), and `settings.backgrounds[game]` names the file; **Reset** deletes the copy and goes back to `img/covers/<game>.jpg`. The bundled cover stays as the layer under the picked one, so a missing file shows the cover. **Darken** (0–80 %, `settings.bgDarken[game]`) lays a dark layer over the picture (`--bg-darken` on `.hero-bg::before`) so a bright one keeps the text readable. The uninstaller removes `backgrounds\`; updates keep it. `--preview-backgrounds` with `--snapshots=<dir>` shows AC with Rally's cover, darkened 40 %.
- **EVO catalogue:** official cars (`system\cars.table` + car-select thumbnails) and tracks (`system\tracks.table` + layout photos and SVG maps from `uiresources\images`) are read from `content.kspkg` and cached in `.cache\evo\base\`. The first scan takes about 30 seconds.
- **Installing mods:** drop a `.zip`, `.rar`, `.7z`, `.kspkg` or `.pak` anywhere on the window, or use **＋ Install mod** on the Mods page. Archives are extracted with Windows' built-in `tar.exe` (libarchive: zip, 7z, rar and rar5) into `%TEMP%\acl-import`. - **Trailers:** pulled from the Steam store API. They are HLS streams, played in the app with `hls.js`.

## EVO packages (.kspkg)

`js/kspkg.js` reads EVO packages without unpacking them. The format comes from [Nenkai/ACEvo.Package](https://github.com/Nenkai/ACEvo.Package) (MIT):

- **File table:** the last 64 MB of the file (32 MB before EVO 0.7), XOR'd with `0x9F9721A97D1135C1`. Each entry is 256 bytes: name, flags, size and offset.
- **Name and brand:** read from `*.moddedcarcontent` (protobuf).
- **Variant labels:** read from `presets/*.visualcarpreset`.
- **Thumbnails:** `generated/thumbnails/*.texture` holds a protobuf header (width, height, format 34 = BC7, 256×256 tiling) and `*.texturemips` holds the BC7 blocks, stored tile by tile. `js/bc7.js` decodes them. It's a port of [bcdec](https://github.com/iOrange/bcdec) (MIT/Unlicense).
- **Framing** (`frameCar`, mod cars only): EVO renders its car pictures on a grey studio backdrop, the car and its shadow across at most ¾ of the width and ½ of the height. Some mods ship theirs closer, the car touching the sides, so their cards looked zoomed in. Measured on a 128 px copy (the backdrop's grey from the border's median; car and shadow are the pixels clearly lighter, darker or more colourful), such a picture is redone at EVO's framing: the backdrop without the car is filled in on a 32 × 32 grid, and the car alone (picture minus backdrop) is put back on it smaller and centred, so no edge shows. Pictures already framed like EVO's, ones that aren't square, and ones whose border or top isn't mostly backdrop (a photo) are left as they are. About 10 ms a picture, 80 ms for one that's redone, next to some 250 ms to decode it. Framed pictures carry `-f<FRAMING>` in their names (the manifest and Quick Drive's livery index note it too), so a new `FRAMING` redoes them once. The cache cleanup (`pruneCache`) removes only files named after a package key that's gone (manifests, pictures, `presets-`, `trackreg-`, `trackmap-`); `known-cars.json` and the game package's presets stay.

- **Writing one** (`writePackage`, for EVO track folders the installer finds): the files' data one after another, then the table, as EVO's own and car mods' are. An entry per file and per folder from the mod's own folder down (`content\tracks\<id>`, as car mods start at `content\cars\<id>`); the name hashed with FNV-1a 64 over the lower-case path in UTF-16 with `\`s (the hash at byte 0xE8), entries sorted by it (EVO finds files by binary search); only the table XOR'd. The progress counts the 64 MB table too, and a failed or stopped write removes the `.part`. `packEvoTrack` puts the folder at `content\tracks\<id>`, and its `ui\photo` and `ui\map` also where EVO's menus look for a track's picture and map: `uiresources\images\tracks\<name>-<layout>.texture`, and `uiresources\images\trackmaps\<name>-<layout>.svg` plus `.texture` (from `ui\map.texture`; the in-game map loads the texture), with the track and layout names it is listed under (`evoUiTrackId`, after `ksUI.getTrackId` in EVO's `uiresources\js\components.js`: the names joined by `-`, spaces as `_`, lower case, e.g. `ek_tsubaki_line-downhill_real`). Those are left out if one would come first in the table, since readers find a package by its first entry being under `content\`. Written as `<id>.kspkg.part`, renamed when done.
- **Mod track names** (`evoTrackName`): EvoForge writes `ui\previews.json`, whose `sources.photo` path names the Assetto Corsa track it was converted from (`…\content\tracks\ek_tsubaki_line\ui\…`). That folder name, prettified, reads better than the converted id (`ek_tsubak_hv`), so the review dialog, the Mods page and EVO's track list use it. Layout names are the layout ids, prettified ("Downhill Real").

## EVO track list (`evotracks.js`)

A track package in the mods folder loads, but EVO never lists it. EVO takes its tracks only from two tables inside `content.kspkg`: `system\tracks.table` and `system\track_containers.table`. Cars have a "modded car" record (`*.moddedcarcontent`) that a package can carry; tracks have none. EvoForge edits `content.kspkg` for the same reason. The launcher adds every enabled mod track to those tables, and takes them out again.

- **The records:** both tables are `TableData` messages (from `CustomTable.proto`; the schema is embedded in the exe). Lines are in `preset` (2) › `lines` (3); a line's field 2 is a `TrackContentData` and field 8 a `TrackContainersContentData` (`LogicScene.proto`).
  - **The track:** name, nation, continent, coordinates, time zone (`DateTime.proto` `TimeZone`), `content\tracks\<id>` with its `.scene` and `.track`, and `is_release`.
  - **Per layout,** as EVO's own (Laguna Seca, Brands Hatch, Suzuka), each with the containers it loads (`container_paths_to_add`):
    - "No Game Mode" (the base layout): `layout_<layout>.scene` and the pit lane zones.
    - "<Layout> Race" (`is_instant_race`): timelines, grid and pit lane spawn points. Max drivers is the grid's "Start Pos" spots.
    - "<Layout> Time Attack" (Practice): timelines and the pit lane spawn points. Max drivers is the pit lane's spots, at most 32 as in EVO's own.
    - "<Layout> Hotstint": timelines and the hotlap spawn point.
  - **Which layouts:** each `containers\layout_<layout>.scene`, as on all of EVO's own tracks (only Brands Hatch and Imola also have `.track_layout` files), plus each `layouts\<layout>.track_layout` (`evoTrackLayouts` in kspkg.js; the installer, the packer and the track list all use it). A layout without an AI line (`layouts\layout_<layout>.ideal_line.aisplinedata`) gets no Race record: the AI cars drive that line. Assetto Corsa layouts without one, such as EK Tsukuba Fruits Line's free roam, convert without it, so Quick Drive offers them for Practice only ("No AI line: practice only"). Tested in game: Tsukuba drives fine in Practice. A track package that can't be listed says why, in the log and in Settings ("Can't be added: … (no layouts …)").
  - **Container files:** a layout's own file comes first (`spawnpoints_grid_<layout>`, `_layout_<layout>`, `timelines_<layout>_default`), then the shared one.
  - **Why the base layout's container matters:** EVO finds the layout's AI line through its `layout_<layout>.scene` (`layouts\layout_<layout>.ideal_line.aisplinedata`). Without it the log says "no ideal line" / "no simulated reference", and the car falls through the road. Test in game: the first version, which listed no containers, did exactly that.
  - **Embedded copies too:** a converted track's main scene also embeds these containers, as EVO's own do.
  - **Common to every layout record:** test stage 10 (LiveContent), the first layout as default, and the map-image numbers from `previews.json` `layoutImage` (margin, min x/y, k, offset x/y = `TrackLayoutImage`).
  - **No length:** the length isn't in the mod, and EVO's menus hide it when it's 0.
  - **No dynamic track:** EVO looks for `dynamic_track\<layout name>.dynamictrackpresetcompressed`. Converted tracks have none, so the log shows "DynamicTrack preset not found", which is harmless.
- **Where the track is:** EvoForge writes the Assetto Corsa track's coordinates into the scene's `track_info` node (`SceneTrackInfo`: name, coordinates, time zone). Its time zone is often left as the UK's, so the country is the nearest of a list of countries to the coordinates (`countryOf`), and the continent and time zone come from the country. Without coordinates the track is listed as in Italy.
- **Writing `content.kspkg` (69 GB):** EVO pads its data to a 1 MiB boundary before the file table. In 0.9.1 that is 887,677 bytes of zeros; the two tables take about 90 KB.
  - The tables are written again, original lines first, with the mod tracks' lines appended (a track whose folder is already listed, e.g. by EvoForge, is skipped). They go into that padding, XOR'd as before, and their two table entries get the new offset and size.
  - The original tables stay where they were, the file keeps its size, and nothing else changes.
  - Before the first change, the padding and the two entries are saved: `.cache\evo\track-list\track-list-backup-<size>.bin`, plus the state in storage (`evoTrackList`, per `content.kspkg` path).
  - The writes go through a small PowerShell `FileStream` (dd on Linux). The file can't be opened for writing while EVO has it open, and the launcher checks for EVO first. The entry is read back afterwards.
  - Tested on a stand-in package built from copies of EVO's tables (`--import-test` `evoTracks`). After restoring, it matched the original byte for byte.
- **When:**
  - Syncs (`syncEvoTrackList`): after an EVO track is installed, enabled, disabled or uninstalled; before EVO starts from Play, Quick Drive or the Academy; and 8 s after the launcher starts (not in test runs).
  - The quick check before each start reads just the two entries. A game update or Steam's Verify integrity replaces the file, so the entries no longer match; the old backup is dropped and the tracks are added to the new file.
- **Quick Drive:** `evoModTracks` describes each enabled mod track as the official catalogue does its tracks: name, country, region, and per layout the Practice and Race entries its saves write (`layoutModes`, the same event names and max drivers as the list). The map outline is copied from the package. `scanEvoTracks` adds this to the mod's item, so Quick Drive lists it beside the official tracks and the detail page's Drive button preselects it. None are listed while the list is restored. EVO's own saves after a drive on the mod track hold the same `TrackItem`.
- **Settings › Assetto Corsa EVO · Mod tracks:** shows what is listed, with Add to EVO and Restore original. Restore writes the saved padding and entries back, so the file is byte-identical to before. It also turns the automatic updates off until Add to EVO or the next track install.

Only the table and these few files are read (about 3 MB from an 850 MB package). Decoded thumbnails are cached as JPGs in `.cache/evo/`, keyed by package size and modification time. The official catalogue (`readEvoCatalog`) only notes which texture each car/track picture comes from; pictures are decoded when first shown (`lazyImage`, asked for by the page's image error handler; cards load lazily, so only those near the view ask), on-screen ones first, and the rest one by one in the background a few seconds later (tracks, then cars). On a first run the EVO pages open in ~3 s instead of waiting for 100+ BC7 textures.

## Neutralino gotchas

- The native bridge treats backslashes in strings as escape characters, so the code normalizes paths to `/`. It doubles backslashes in shell commands. File writes go through `writeBinaryFile` and storage values are base64.
- Server mounts match by prefix, so no mount name can be a prefix of another (`/m/assettocorsa`, `/m/competizione`, ...).
- `--snapshots=<dir>` walks every view, saves window snapshots and then exits. It's a visual smoke test.
- `--import-test=<config.json>` runs archives through the installer into sandbox folders, tests the drop path, snapshots the dialogs, writes a report and then exits (see `js/dev-import-test.js`).
