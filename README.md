# Assetto Launcher

I started this project roughly a year ago with a design in mind, made in Figma. I didn't have the coding skills nor the idea sorted out, but thanks to AI I could make this project come to life, and I think it's worth a shot. The code is open source and I would love the community's feedback on things to improve. I think the foundation is pretty good, and while some features may not be as good or as polished as I would like them to be, they are better than nothing.

This is basically just a launcher where you can see all your installed mods from any Assetto Corsa game, and on top of that you can start races with a predefined car and track, like in Content Manager. For the games that aren't the original Assetto Corsa, the car and track are added to a save file, so that when you go into the game after choosing them and launching the game through the launcher, it'll set them as the default. So you already have everything selected. For some games, you can even change the time, weather, opponents and more.

Personally, I really like the project, and I hope the community does too.

---

A lightweight launcher for the four Assetto Corsa games: AC, ACC, EVO and Rally. It lets you browse installed mods visually, read the official Steam news, and launch the games.

Built with [Neutralino](https://neutralino.js.org/), which uses the WebView2 runtime that comes with Windows: no Electron or Chromium bundle. The installer is about 7.5 MB.

## Download

Get the latest version from [Releases](https://github.com/Zelbrad/AssettoLauncher/releases):

- **`Assetto-Launcher-Setup-<version>.exe`**: installs for your Windows user only (no admin prompt), with a Start Menu entry and an optional desktop shortcut. Installing a newer version keeps your settings.
- **`assetto-launcher-release.zip`**: portable. Unzip anywhere you can write to and run `assetto-launcher-win_x64.exe`.

Needs Windows 10 (1803 or later) or 11 and the games from Steam. It works offline; news, store prices and update checks need a connection.

### "Windows protected your PC"?

The launcher isn't code-signed yet, so Windows SmartScreen warns about it until enough people have run it. Click **More info → Run anyway**. Each release lists the installer's SHA-256 hash, so you can check you have the genuine file (`Get-FileHash <file>` in PowerShell).

## Build from source

1. Install [Node.js](https://nodejs.org/).
2. `npx @neutralinojs/neu update` fetches the Neutralino runtime into `bin\`.
3. `run-dev.bat` runs it straight from `resources\`; `build.bat` packages it (see below). The installer needs [Inno Setup 6](https://jrsoftware.org/isinfo.php).

## What it reads

| Game | Content | Preview image |
|---|---|---|
| Assetto Corsa | `<install>\content\cars\*`, `content\tracks\*` | `skins\<skin>\preview.jpg`, `ui\badge.png`, track `ui\[layout\]preview.png` + `outline.png` |
| AC Competizione | `Documents\Assetto Corsa Competizione\Customs\Liveries\*` + `Customs\Cars\*.json` | `preview.*`, `decals.png`, `sponsors.png` |
| AC EVO | `Saved Games\ACE\mods\*.kspkg`, and external liveries in `Saved Games\ACE\ExternalLiveries\*` | the car-select thumbnails inside the package, one per visual preset (a sidecar `my_car.png` overrides them); `livery_thumbnail.png` for liveries |
| AC Rally | custom liveries in `Documents\My Games\acr\Liveries\<CarId>\<Livery>\` (`livery.json`, `body_livery_*.dds`), and `.pak/.utoc/.ucas` liveries in `<install>\acr\Content\Paks` (+ `~mods`) | the livery's `icon.png`, as in the game; the detail page also shows its `body_livery_albedo.dds` (BC1/BC3/32-bit, decoded by `dds.js` into a 1024 px JPEG cached in `.cache\rally`), which is the card picture when there is no icon; for paks, an image with the same name. Rally cards are square |

Install folders are found automatically through Steam (`libraryfolders.vdf` + `appmanifest_*.acf`). You can change any folder in **Settings**.

- **Mods vs Kunos (AC):** content counts as a mod when its `author` isn't Kunos, or when its folder isn't a known Kunos ID.
- **Enable / disable (EVO, Rally):** the launcher renames the files with a `.disabled` suffix. The game ignores renamed files, and enabling them again just removes the suffix. Rally loads every folder under `Liveries\<Car>`, so a disabled custom livery is moved to `Documents\My Games\acr\Liveries (disabled)\<Car>\` instead.
- **Uninstall:** a mod's detail page has an Uninstall button (click it twice to confirm). Everything that belongs to the mod goes to the Recycle Bin, so it can be restored: the AC folder, the ACC livery plus the car files that use it, the EVO package plus its image, the EVO livery plus its garage car, or the Rally livery folder or pak trio plus its image. Official content can't be uninstalled.
- **Quick Drive (navbar):** works the same whichever game is selected in the sidebar. The dialog has a tab per game (Assetto Corsa, EVO and Competizione; Rally is shown but not available) and opens on the sidebar's game when it has Quick Drive, else on the one used last. The **Session settings** button in its header opens a sheet with everything the game lets you set for the session (below); the header and footer show a summary. Closing the dialog without launching still remembers the car, livery/skin, track, layout and session.
- **Quick Drive (AC):** car, skin, track/layout and session are written to `Documents\Assetto Corsa\cfg\race.ini`, then `acs.exe` starts directly, the same way Content Manager does. The keys, ranges and formulas are the ones AC's own launcher uses (`launcher\themes\default\js\ui.js`); assists and CSP settings are left as they are. The first time, the original file is backed up as `race.ini.launcher-backup`.
  - **Modes:** Practice (length or unlimited), Hotlap, Race (laps, starting position: last, random or a slot) and Race Weekend (practice or skip, qualifying, race laps), as `[SESSION_n]` sections.
  - **Opponents (races):** count (up to the layout's pit boxes − 1), strength (`[RACE] AI_LEVEL`, 80–100 %), variation (each car's `AI_LEVEL` below 100) and aggression (`AI_AGGRESSION`, 0–100). They drive your car in its other skins, named from each skin's `ui_skin.json` or AC's `namesnat.txt`. Layouts without `ai\fast_lane.ai` can't have opponents and are marked "no AI line".
  - **Conditions:** time of day (08:00–18:00, `SUN_ANGLE`), time speed, weather (`content\weather`), air temperature (10–36 °C), track temperature (Auto uses AC's launcher formula with the weather's `TEMPERATURE_COEFF`), track grip (the presets in `cfg\templates\tracks.ini`) and penalties. With Content Manager's CSP keys present, `__CM_WEATHER_TYPE` is kept in step with the weather, and the previous track's `__TRACK_*` location keys are removed.
  - Tracks without any `.kn5` (unowned DLC placeholders, or mod layouts that need such a DLC) aren't listed.
- **Quick Drive (EVO):** pick the session, track/layout and car, and the launcher starts EVO through Steam (`steam.exe -applaunch 3058630 -no_intro`). In EVO, **Single Player** shows everything already selected. Started directly, the exe can fail Steam's ownership check. The session sheet has what EVO's own Game Mode and Weather pages can change, with the same ranges: mode (Practice, Race, Race Weekend); each session's length, start time and time speed (Race: laps or time, starting position); the AI grid (automatic or EVO's custom grid, opponents up to the layout's limit, skill from/to 80–100 %, single make); weather preset, static/dynamic and initial grip (Green, Fast, Optimum). EVO has no temperature setting. Field numbers come from the protobuf descriptors embedded in the EVO exe (`GameModeSelectionClientCommands.proto`). The launcher edits these save files under `Saved Games\ACE`, keeping a `.launcher-backup` of each:
  - **Sessions:** in `GameModes\GameModeType_PRACTICE|INSTANT_RACE|RACE_WEEKEND.gamemodesave`, each session's `track_item` (5), duration (2) and type (3, time or laps), `time_of_day` (4: hour, minute, time multiplier) and, for Race, `starting_position` (22). The AI grid is in the first session: `grid_type` (6), `num_opponents` (7), `single_make` (12), `min_strength`/`max_strength` (30/31) and `aggressivness` (32: always 1, Safe; the game ignores its other value, "Preview"). Practice uses each layout's "Time Attack" entry in `system\track_containers.table`, the races its "Race" entry. A mode EVO hasn't opened yet starts from its default save in `content.kspkg`.
  - **Selected mode and weather:** `GameModes\gamemode.lastgamemode` (`type` = 1, `weather_type` = 2); static/dynamic (2) and initial grip (6) go into the selected preset's `weather_data` entry, as EVO's weather page does.
  - **Car:** the current-car ID (field 4) in `ProfileData\<profile>\OpenData\garage.drivergarage`.

  EVO creates a car ID per exact configuration (car + mechanical preset + livery) and doesn't expose them. So only configurations it has already used can be picked; garage cars (`SavedCars`) can't be selected this way, because EVO falls back to another car. Every car is listed, and cars without an ID are marked "Not used yet". The launcher reads IDs from EVO's logs: the preset screen logs `Selected <car> <mech preset> <visual preset>`, and the last such line before `Set new car <id> …` names that ID's livery. It also checks `last_season.seasondefinition`. A selected car shows a compact **Livery** row with each known livery's thumbnail and name (`generated\thumbnails\<car>-<mech>-<visual>.texture` and the `.visualcarpreset` / `.mechanicalcarpreset` names, from `content.kspkg` or the mod package), cached in `.cache\evo\extras\`. EVO keeps only its last ~10 logs, so found IDs are saved in `.cache\evo\known-cars.json`.
- **Brand rail (Mods > Cars, AC and EVO):** the same brand column as Quick Drive filters the car grid (AC: each brand's car badge; EVO: its brand logos from the package, cached by `readEvoExtras`). It follows the search and the Mods/All filter. On these pages the page itself doesn't scroll: the rail and the car grid scroll separately, and picking a brand keeps the rail where it is. Car cards show the brand logo top left (AC: the car's badge; EVO: its brand's logo, set as `badge` once the logos load), and the detail page shows it above the title.
- **Window:** borderless (own title bar), so Windows gives it no resize frame: `windowGrips` puts thin grips on the edges and corners that resize it through `Neutralino.window.setSize`/`move` (hidden while maximized; pointer moves that arrive before the window's size is known are replayed). The default size, 1540×795, is also the minimum. Every resize goes through `setWindowSize` with `resizable: false`: Neutralino's `setSize` otherwise adds `WS_THICKFRAME`, which shows as a strip above the title bar (restoring the saved size at launch does too, so startup calls it once). `roundCorners` asks Windows 11 for small rounded corners (`DwmSetWindowAttribute`, `DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_ROUNDSMALL`, through `powershellEncoded`), which keeps the window shadow; older Windows ignores it.
- **EVO livery names:** a car EVO loads from the garage at session start has no "Selected" log line before it; the car menu's first "Selected" line after "Set new car" (same mechanical preset) names its livery, so `knownCars` fills it in when unknown. Visual preset `*_visual_99` is EVO's slot for an external livery: Quick Drive shows that livery's `livery_thumbnail.png` and name from `ExternalLiveries` (matched to the car through its `car_guid` in SavedCars) instead of the package's plain white car.
- **Quick Drive picker (AC, EVO, ACC and Rally):** car column with a thin brand rail (EVO's `uiresources\branding\oem\<brand>\logo.texture`; for AC, the cars' `ui\badge.png`), a car grid and a one-line skin/livery row (the selected car's card shows the chosen one); track column with layouts and a track grid. Both columns have their own search. Quick Drive is a page (navbar), not a dialog: the game sidebar is hidden there (`#app.qd-mode`), and `qdPage` only swaps in a game's page if it's still the one asked for (`state.qdWant`), so switching tabs keeps the current page dimmed until the next game's lists are ready, then fades them in. Rally locations show a photo cover (`img/rally/<location>.jpg`, Wikimedia Commons, credits in `img/rally/CREDITS.txt`) with the country's flag in the corner (Wales: the Welsh flag); ACC tracks show their country's flag (`img/flags/<iso>.png`, flagcdn.com). Rally's own car pictures, logos and stage maps exist (`acr/Content/Data/UITextures/Cars`, `CarsLogo`, `Tracks/Tracks/T_*_Map`, found through the IoStore directory index) but are Oodle-compressed, and no Oodle library ships with the games. Rally Quick Drive also sets the main menu car, which is the most recently driven one (read at startup): the chosen car gets "now" in the car → last-driven map (`int32 k, k × FString car, 8 zero bytes, int32 m, m × (FString car, int64 .NET ticks, local time)`), added if missing. It sets the livery too: the save ends with a car → livery map (`int32 count, count × (FString car, FString livery)` up to the end of the file; a car's own livery is its id, a folder livery `usergen_<folder>`; tested in-game). The Livery row lists the car's own livery (or the enabled .pak that replaces it), the game's other liveries once the save has had them selected (learned, `settings.rallyLiveryIds`), and the folder liveries. `RALLY_KNOWN_STAGES` lists all 46 stages: the variants of the pacenote tables in the game's packages (`Data/Pacenote/Tables/DT_Pacenote<Stage><Variant><Direction>`) for the 9 stages with an `Environments` folder (Alsace S2 Munster, S4 Saverne; Greece S3 Elatia, S4 Loutraki; Livigno; Monte Carlo S1 Bollène/Col de Turini, S2 Sisteron; Wales S3 Hafren North, S4 Hafren South), with the save's id naming.
- **Official pictures (ACC, Rally):** `tools/site-images.mjs` downloads the car, stage and track pictures from assettocorsa.gg (`sitecatalog.js` parses the pages' `#cars` / `#stages` / `#tracks` sections) into `img/site/<game>/` with a `manifest.json` (480 px JPEGs, ~2.4 MB): 18 Rally cars, 9 Rally stage photos (Greece's two aren't in the site's gallery yet: they come from the EA 0.5 news post, `RALLY_STAGE_PHOTOS`), 9 Rally stage maps (the site's `T_<stage>.png` under `<p class="font-script">` captions, `siteMaps`; `tools/map.ps1` crops them to the outline, turns the black start arrow/finish flag light grey and fits them in 160 px, kept transparent; shown on each stage button, drawn white like AC's outlines with a CSS filter so maps synced later match), 62 ACC cars (the GT2 cars aren't named there; they keep their logo) and 25 ACC tracks (the page names DLC packs instead of some tracks, so these follow ACC's alphabetical order). Rally is in Early Access, so at every launch, when online, `siteSync` asks for the Rally page with `If-Modified-Since` (the site answers 304 with no body when nothing changed; a changed page is ~70 KB compressed) and keeps pictures of cars, stages and stage maps added since in `.cache/site` (`settings.siteExtra`, matched to cars by name; entries the launcher now ships are dropped). `node tools/site-images.mjs rally/maps` refetches only the kinds named. Rally's Livery row selects the livery but the car keeps its photo (`keepCarImage`: Rally's livery pictures are flat textures).
- **Offline:** everything local works without a connection (pictures ship with the launcher or are cached); news, store prices, mod update checks and the site sync need it. At startup `checkOnline` asks Steam's store; when offline a one-line note (red outline, red ✕) shows top right for 10 s (`OFFLINE_NOTICE_PREVIEW` shows it while online too, for review). Replays use the launcher's replay icon (`img/replay.png`, drawn by `tools/replay-icon.ps1`), shown small.
- **Quick Drive (Competizione):** ACC can't be started straight into a session (its only launch options are for VR, and its track maps are inside an encrypted package), so this sets up its **Single Player menu** and starts the game; the player presses Start there. Every menu choice is in `Documents\Assetto Corsa Competizione\Config\menuSettings.json`, which ACC reads at startup and rewrites on exit (so it must be closed). The launcher writes `singlePlayerSeason`, `seasonGameMode[season]` (Practice, Hotlap, Hotstint, QuickRace or CustomRace = Race Weekend), the mode's `seasonRaceEventData[season].raceEventData[mode]` (`carName` = a custom car file from `Customs\Cars`, or left as ACC's own pick; `trackName`, lengths in seconds, `opponentCount`, `positionOnGrid`, `skillMultiplier`, `aggroMultiplier`, `timeOfDay`, `timeMultiplier`), the `global*` opponent values and `weatherType` (Sunny, Cloudy, LightRain, MediumRain, HeavyRain, ThunderStorm, Random). It is written in ACC's own layout (`accJson` in `acclaunch.js`: rewriting an unchanged file gives the same bytes), and the original is kept as `menuSettings.json.launcher-backup`. Track ids are the ACC server's. Cars: ACC's current car, your custom cars, and every ACC car model (`ACC_CARS`); official team entries are only named by code, so driving a model creates a plain custom car `Customs\Cars\Launcher - <model>.json` (UTF-16, `skinTemplateKey` 99 with no `customSkinName`) the first time. Cars, tracks and championship seasons of DLCs the Steam account doesn't own are hidden (custom cars of those models too), so the list matches whoever runs the launcher: `accOwnedDlcs` reads the DLC list from ACC's app ownership ticket that Steam caches in `userdata\<account>\config\localconfig.vdf` (account from the app manifest's `LastOwner`), and `ACC_DLC_CARS` maps each car pack (GT4, 2020 GTWC, Challengers, 2023 GTWC, GT2) to its models, `ACC_DLC_TRACKS` the track packs (Intercontinental GT, British GT, American, 24H Nürburgring, plus the tracks of the 2020/2023 GTWC and GT2 packs) and `ACC_DLC_SEASONS` their championships. When ownership can't be read, everything is listed. ACC's own pictures are inside its encrypted package (whether a pack is owned or not), so models show their brand logo (EVO's logos, AC's badges) and tracks show initials.
- **Quick Drive (Rally):** Rally has no launch option for a stage (a level on the command line is ignored or crashes it), so, like ACC, it pre-selects the Free Practice menu: Rally opens Free Practice on the stage, car and event start time stored in `%LOCALAPPDATA%\acr\Saved\SaveGames\PlayerDataSaveSlot.sav` (`rallylaunch.js`). That GVAS save has no properties; its data is a blob after the FString `PlayerSaveGameData` and an int32 size that runs to the end of the file. The selection is two FStrings (stage id, car id), an option count (3) and key/value FStrings for `WeatherOptions/StartingTime` `(TimeSeconds=…)`, `Preset` and `TimeSpeed`. Only stage, car and start time are written (tested in-game: the saved weather and time speed are ignored, the player picks them in Weather & Time), the size is fixed, the result is re-parsed before saving, the previous file is kept as `.launcher-backup`, and it refuses while `acr.exe` runs (Rally rewrites the save on exit). Stage ids (`<Location>[S<n>]<Stage><Full|CutN|ShortN><Forward|Reverse>`, e.g. `WelesS4HafrenSouthFullReverse` = Severn → Afon Bidno) only exist in the save once driven, so the picker lists the stages seen there, remembered in the settings (`rallyStages`). Cars show brand logos (EVO/AC), as for ACC.
- **Brand logos (ACC, Rally):** EVO's logos (`uiresources\branding\oem`), else AC's car badges, else the launcher's own `img/brands/<brand>.png` for brands neither game has (Aston Martin, Bentley, Citroën, Fiat, Ginetta, Jaguar, Lexus, Škoda, Subaru): Wikipedia/Wikimedia emblems cut to the emblem, dark parts turned white and fitted to 128×128 like EVO's. Rally's and ACC's own car and stage pictures can't be used: ACC's package is encrypted and Rally's IoStore containers are Oodle-compressed (no Oodle library ships with any of the games).
- **Game updates:** `findInstalledApps` also records each app manifest's `buildid` and `LastUpdated` (`appBuilds`). The launcher remembers the build per game (`settings.builds`); when it changes, the game's Games and Mods pages show a note until dismissed (`settings.updateNotes`): Rally lists the .pak liveries whose utoc version no longer matches (they crash the game), EVO warns when mod packages are installed, AC mentions CM/CSP. ACC has none (its liveries survive updates), and a note clears itself when nothing applies.
- **Presets and recent sessions (Quick Drive, every game):** ☆ Presets saves the selection (car, skin/livery, track, layout) plus the session settings (`session.get/set` per game) under a name (`settings.qdPresets[game]`); the last 8 launched sessions are kept in `settings.qdRecent[game]`. Loading skips a car or track that no longer exists and says so.
- **Personal bests (`bests.js`):** AC from `Documents\Assetto Corsa\personalbest.ini` (`[CAR@TRACK-LAYOUT]`, TIME ms, DATE epoch ms); EVO from `Saved Games\ACE\Results\*.sessionresults.json` (the player's `best_lap` by track, layout and car display name; EVO doesn't always flag the player, so the flagged driver's name counts too); Rally from the save's stage records (per stage: FString stage, int32 count, then per car: car, class, weather FStrings, u32 total ms, u32 penalty ms, u32 split count, splits, int64 .NET ticks; splits + penalty = total). ACC keeps no readable lap history. The Quick Drive footer shows the best for the selected car and track ("beat it"), and the Presets sheet lists them with a Beat it button that selects that car and track.
- **Screenshots and replays (`media.js`, Mods page tabs):** Steam screenshots (`<Steam>\userdata\<account>\760\remote\<appid>\screenshots`) for every game plus AC's `Documents\Assetto Corsa\screens`; replays from AC `Documents\Assetto Corsa\replay\*.acreplay`, ACC `Replay\Saved|Highlights\*.rpy`, EVO `Saved Games\ACE\Replay\Saved\*.rpy` (Rally keeps none, so it has no Replays tab). Newest first; Open picture, Open folder and Delete (Recycle Bin, with Steam's thumbnail).
- **Mod check (`health.js`, Mods page "Check mods"):** AC cars without data.acd/data or .kn5 or skins, tracks without a .kn5 (extra layouts of a missing base track or DLC) and layouts without an AI line; EVO packages that can't be read and two enabled packages adding the same car; ACC liveries no car file uses (grouped) and car files pointing at a missing livery folder; Rally .pak liveries for another game version (with Disable) or missing their .utoc/.ucas, several .pak liveries for one car, folder liveries without their texture or icon.
- **Mod updates (`updates.js`, AC):** Content Manager's update registry (CUP): `https://acstuff.club/cup/list` gives the latest version of every registered car and track (`{ car: { id: "1.2" | { version, limited } }, track: … }`), `/cup/<kind>/<id>` the changelog, `/cup/<kind>/<id>/get` redirects to the download. AC mods whose `ui_car.json` / `ui_track.json` version is older get an "Update" flag, a "Get update" button and the changelog on their detail page, and show in the mod check. EVO, ACC and Rally mods have no registry (their files carry no version or source), so they can't be checked.
- **Surprise me (Quick Drive):** a random car (and livery/skin) and a random track and layout among the ones the game can start with; session settings stay.
- **Game settings backups (`backups.js`, Settings page):** copies of each game's settings, setups and progress (AC: `cfg`, `setups`, `champs`, `personalbest.ini`; ACC: `Config`, `Setups`; EVO: everything in `Saved Games\ACE` except mods, liveries, logs, replays, MoTeC, results and crash dumps; Rally: `Saved\Config\Windows`, `Saved\SaveGames`) in `Documents\Assetto Launcher\Backups\<game>\<date>\` with a `backup.json`. Copies go through PowerShell `Copy-Item` (single-quoted forward-slash paths); the launcher's `.launcher-backup` files are left out. Restoring refuses while the game runs, backs up the current state first and merges the files back. One automatic backup per game each week; the last 4 automatic ones are kept.
- **EVO catalogue:** official cars (`system\cars.table` + car-select thumbnails) and tracks (`system\tracks.table` + layout photos and SVG maps from `uiresources\images`) are read from `content.kspkg` and cached in `.cache\evo\base\`. The first scan takes about 30 seconds.
- **Installing mods:** drop a `.zip`, `.rar`, `.7z`, `.kspkg` or `.pak` anywhere on the window, or use **＋ Install mod** on the Mods page. Archives are extracted with Windows' built-in `tar.exe` (libarchive: zip, 7z, rar and rar5) into `%TEMP%\acl-import`. The launcher then works out the game and the target folder from the layout, at any depth and through archives nested in archives:

  | Recognised | Installed to |
  |---|---|
  | AC car (`ui/ui_car.json`, `data.acd` or `data/car.ini`) | `content\cars\<folder>` |
  | AC track (`ui/[layout/]ui_track.json`, `models*.ini`, or `.kn5` + `data/surfaces.ini`) | `content\tracks\<folder>` |
  | AC skin (`ui_skin.json`, or `livery.png` + `preview.jpg`) | `content\cars\<car>\skins\<skin>`, with the car taken from the path or archive name, or picked by the user |
  | AC root layout (`content/…`, `apps/python|lua`, `extension/` + CSP's `dwrite.dll`) | merged into the AC folder |
  | ACC livery folder (`decals`/`sponsors` `.json`/`.png`) and car files (`.json` with `carModelType`) | `Customs\Liveries\…`, `Customs\Cars\…` |
  | EVO `.kspkg` (+ same-name image) | `Saved Games\ACE\mods` |
  | EVO external livery (`external_livery.json`, e.g. LiveryLab Evo packages) and its car (`<car>_<car_guid>.carfinalstatewithconsumable`) | `Saved Games\ACE\ExternalLiveries\<folder>` + `ProfileData\<profile>\OpenData\SavedCars` (most recently used profile) |
  | Rally livery folder (`livery.json` + `icon.png`/`body_livery_*.dds`) | `Documents\My Games\acr\Liveries\<CarId>\<folder>`. The car is guessed from the name ("206" → `Peugeot206`, "i20" → `Hyundaii20NRally2`, see `RALLY_CARS` in `games.js`) and can be changed. If the archive also has the same livery as a `.pak` with a matching name (e.g. `KRUUDA/` + `2014_Kruuda_208_P.pak`), only the folder is installed |
  | Rally `.pak` + `.utoc` + `.ucas` (+ image) | `acr\Content\Paks\~mods`. An archive preview such as `00.jpg` is installed as `<pak name>.jpg`. A pak whose IoStore version (byte 16 of the `.utoc`) differs from the game's `global.utoc` was cooked for another game version and crashes Rally at startup ("Trying to resize TArray to an invalid size"), so it starts unchecked. Installed ones are flagged "Crashes game", and **Play** offers to disable them first |

  A review dialog lists each item with its target, marked New or Update, before anything is copied. Updates are copied over the existing folder, so files the user added (extra skins, for example) are kept. An older `.disabled` copy of an EVO or Rally mod is replaced. Dropped files come from the webview without a path. The launcher finds the original in Downloads, on the Desktop or in Documents by name, size and first 64 KB; if it isn't there, it copies the file into the temp folder first. Password-protected archives aren't supported.
- **News:** from the Steam News API (official announcements only), cached so it shows instantly and offline. At every launch, when online, each game is checked in the background (`refreshNews`: a request for just the latest post's id, ~0.5 KB; the full list is fetched only when that changed), and an open page updates when something new arrives. Nothing waits on the network to draw.
- **Trailers:** pulled from the Steam store API. They are HLS streams, played in the app with `hls.js`.

## EVO packages (.kspkg)

`js/kspkg.js` reads EVO packages without unpacking them. The format comes from [Nenkai/ACEvo.Package](https://github.com/Nenkai/ACEvo.Package) (MIT):

- **File table:** the last 64 MB of the file (32 MB before EVO 0.7), XOR'd with `0x9F9721A97D1135C1`. Each entry is 256 bytes: name, flags, size and offset.
- **Name and brand:** read from `*.moddedcarcontent` (protobuf).
- **Variant labels:** read from `presets/*.visualcarpreset`.
- **Thumbnails:** `generated/thumbnails/*.texture` holds a protobuf header (width, height, format 34 = BC7, 256×256 tiling) and `*.texturemips` holds the BC7 blocks, stored tile by tile. `js/bc7.js` decodes them. It's a port of [bcdec](https://github.com/iOrange/bcdec) (MIT/Unlicense).

Only the table and these few files are read (about 3 MB from an 850 MB package). Decoded thumbnails are cached as JPGs in `.cache/evo/`, keyed by package size and modification time.

The UI is laid out on the Figma frame's 1920×991 canvas using its pixel values. `main.js` zooms the page to fit the startup window. A bigger window (maximized or resized) keeps that zoom and gets more room instead: the navbar, sidebar, buttons and news cards keep their size, the hero image grows, the hero logo and text scale up with the window (75 % of the extra room), and the Mods and Quick Drive grids add columns. A smaller window zooms out. `--snapshots=<dir> --maximize` takes a short snapshot pass in a maximized window. The Mods, Community and Settings pages render 1.2× larger for readability (`--page-zoom`).

## Neutralino gotchas (already handled)

- The native bridge treats backslashes in strings as escape characters, so the code normalizes paths to `/`. It doubles backslashes in shell commands. File writes go through `writeBinaryFile` and storage values are base64.
- Server mounts match by prefix, so no mount name can be a prefix of another (`/m/assettocorsa`, `/m/competizione`, ...).
- `--snapshots=<dir>` walks every view, saves window snapshots and then exits. It's a visual smoke test.
- `--import-test=<config.json>` runs archives through the installer into sandbox folders, tests the drop path, snapshots the dialogs, writes a report and then exits (see `js/dev-import-test.js`).
